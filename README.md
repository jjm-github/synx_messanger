# synx messenger

Отдельное веб-приложение-мессенджер, вычлененное из `synx_engine`.
За основу взят layout правой панели **«Люди»**, когда она откреплена в
отдельное окно браузера: слева список пользователей, справа личный чат.

## Что перенесено

- список активных пользователей: аватар, онлайн-статус, количество
  подключений, непрочитанные, последнее сообщение;
- личные сообщения с вложениями, картинками, правкой своих сообщений,
  подсказкой `@short_name`, копированием/сохранением картинок;
- автообновление списка и открытого диалога;
- статусы присутствия: «в сети», «отошёл», «не беспокоить», «не в сети»;
- **аудио-комнаты**: создание комнаты, приглашение в личный чат, вход по
  двойному клику/по ссылке, микрофон, mute, индикаторы громкости,
  настройки режима (серверный миксер / WebRTC) и битрейта;
- тема оформления synx (та же система цветовых схем);
- вход по тем же пользователям, что и в synx engine.

## Что убрано

- «лампочка» и всё вещание (`broadcasters`, экран/плеер, общий чат
  вещания, связи вещания на панели);
- проекты, сущности, задачи, версии, публикации, комментарии к ним;
- события, плеер, paint, админка и прочие разделы движка.

## Запуск

Нужен Python 3.11–3.12: серверный аудио-микшер использует модуль
`audioop` (в Python 3.13 он удалён).

```bash
cd /home/jaroslav/Dev/synx_messenger
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# отредактируйте .env под свою базу и хранилище
set -a; . ./.env; set +a
python -m app.manage init-db
uvicorn app.main:app --host 0.0.0.0 --port 8020
```

Или, после создания `.env`, одной командой:

```bash
./run.sh
```

Откройте `http://127.0.0.1:8020/`.

### Общая база с synx engine

Мессенджер можно нацелить на существующую базу движка — тогда
пользователи, личные сообщения и аудио-комнаты общие. Укажите тот же
`SYNX_DB_DSN` и `SYNX_STORAGE_PATH`, что в `synx_engine/.env`.
Команда `init-db` безопасна: все объекты создаются через
`IF NOT EXISTS`. Пользователи уже есть — создавать их не нужно.

Кука сессии называется `synx_session` так же, как в движке. На одном
домене (даже на другом порту) вход общий: авторизация в synx engine
сразу действует и в мессенджере, и наоборот.

### Отдельная база

```bash
python -m app.manage init-db
python -m app.manage create-user v.dolgih "Василий Долгих" пароль
python -m app.manage create-user a.admin "Админ Админов" пароль --admin
```

Сменить пароль:

```bash
python -m app.manage set-password v.dolgih новый-пароль
```

## Аудио

По умолчанию приложение поднимает собственный микшер на
`127.0.0.1:8011` и проксирует его через `/api/audio/{room}/ws`.
Если рядом уже запущен synx engine, порт занят его микшером — это
нормально: мессенджер подключится к общему микшеру, и участники из
движка и мессенджера будут слышать друг друга. Для полностью
изолированной установки задайте другой `SYNX_AUDIO_PORT`.

Микрофон в браузере работает только на `localhost` или по HTTPS.
Для доступа по сети настройте TLS reverse-proxy (nginx) и включите
`SYNX_COOKIE_SECURE=true`.

## Ограничения

- Вложения личных сообщений физически лежат в
  `SYNX_STORAGE_PATH/direct/<пара>/<message_id>`; старые вложения
  движка читаются из того же хранилища.
- Удаление сообщений не включено (в исходной панели у личных
  сообщений тоже не было удаления): доступны отправка, вложения и
  правка своих сообщений.
- Счётчик непрочитанных и последнее сообщение обновляются опросом
  раз в 5 секунд, открытая лента — раз в 12 секунд.
